# Release v1.0.0 — "Inaugural Production Release"

**Date:** 2026-07-04
**Tag:** `v1.0.0`

The first formally versioned release of the turnbased-cards-demo project.
This release consolidates the completed production roadmap (four epics:
client performance, server scalability, observability, and QA/security) with
a final hardening pass, dependency cleanup, repo hygiene, and version
reporting.

---

## Highlights

- **Production roadmap complete.** All four epics shipped: client performance
  & rendering, server scalability & architecture, observability & monitoring,
  and quality assurance & security.
- **First versioned cut.** Package versions bumped to `1.0.0` across the root,
  server, web client, and R3F showcase. Version is now reported via the server
  `/healthz` endpoint and the web lobby footer (single source of truth:
  `package.json`).
- **Clean dependency audit.** `npm audit --omit=dev` reports **0
  vulnerabilities** on both server and client.
- **26 MB of orphaned dev artifacts removed** from the repository.

---

## Added

### Server
- **Game-duration Prometheus metric** — `UnoRoom` now records `gameStartedAt`
  on round start and observes the completed game length into the
  `game_duration_seconds` histogram, so `/metrics` reports real game lengths.
- **Seat-takeover helper** — extracted `assignSeatToClient()` so the
  bot-seat takeover consistently cancels pending bot-turn callbacks, cleans
  `seatsHandedToBot`, sets up the StateView, locks the room when full, and
  reschedules the turn.
- **Version reporting** — `/healthz` now returns `{ status, version }`
  instead of a bare status, so deployments and monitoring can confirm the
  running build. New `server/src/version.ts` sources the version from
  `package.json`.

### Web Client
- **Connection-error feedback** — new `src/connectionFeedback.ts` translates
  raw Colyseus join/disconnect errors into friendly user messages (server
  unreachable, wrong password, rate-limited join, room not found/locked,
  unexpected disconnect recovery). Wired into the lobby and table flows; a
  `__unoTestHooks.closeCurrentRoom` hook enables smoke-test coverage.
- **Ambient soundscape + new SFX** — `src/audio/sfx.ts` gained a master-gain
  bus (volume slider scales one-shots and ambient uniformly), an ambient
  oscillator bed with teardown on table unmount, and new effects: `playSwish`,
  `playChime`, `playTurnAlert`, `playHeartbeat`, `playUno`, `playError`.
- **Version display** — the lobby footer now renders an unobtrusive
  `v{VERSION}` line. New `web-react/src/version.ts` sources the version from
  `package.json`.
- **Turn UX copy revamp** — clearer turn-guidance and action-callout text.

### Tooling / CI
- **PNG compression regression check** in client CI (Epic 1.3.4).
- **Coach smoke check** added to the web client smoke suite.
- **Release runbook** — new `docs/releases/README.md` documenting the
  cut-a-release process.

### Docs
- Redis presence incident runbook (`docs/incident-response/redis-presence-lost.md`).
- Bot timing side-channel documentation (Epic 4.3.4).
- Compose plans directory.

## Changed

- **Spectator password bypass** — spectators can now join a private table
  without the password, so a host can share a private-table invite with
  viewers without leaking the passcode. Active players still require the
  password.
- **DOM-mutation TurnTimerRing** — `TurnTimerRing` refactored from
  React-state-driven re-renders to direct DOM mutations, eliminating
  per-animation-frame React re-renders.
- **Stale doc references** — `docs/protocol.md` and `docs/security.md`
  updated to reference `sanitizePlainText()` instead of the removed
  DOMPurify dependency.
- **`server/tsconfig.json`** — enabled `resolveJsonModule` (required for the
  version import).

---

## Fixed

- **Rematch-vote wipe on disconnect** — `onLeave` now only drops the
  *departing* player's own rematch vote instead of wiping ALL votes, so a
  single disconnect no longer discards everyone's rematch request.
- **DOMPurify advisories** — removed the unused `dompurify` and
  `@types/dompurify` dependencies (chat/name sanitization was always handled
  by the regex-based `sanitizePlainText()`). This clears the moderate
  DOMPurify CVE.
- **Transitive `ws` DoS advisory** — added `ws: ^8.21.0` to server overrides
  to clear the high-severity ws memory-exhaustion advisory
  (GHSA-96hv-2xvq-fx4p) pulled in by `@colyseus/ws-transport`.
- **CI working-directory** — fixed the PNG check step's working-directory.

## Performance

- `TurnTimerRing` DOM-mutation refactor eliminates per-frame React
  re-renders.
- `React.memo` + stable callbacks on `HandCardItem` / `TableCardAlert`
  reduce per-card re-renders.
- Card PNGs consolidated into a single sprite atlas (137 dead PNGs removed
  earlier in the branch).

## Security

- Helmet, CORS allow-list, and body-size limits via Express middleware.
- Per-message-type rate limiting (chat, UNO calls, join attempts).
- Strict payload validation with Zod schemas for all message handlers.
- Anti-cheat audit: server state filtering (StateView), RNG analysis, bot
  timing side-channel documented.
- Dependency audit: **0 vulnerabilities** on both server and client
  (`npm audit --omit=dev`).

## Upgrade Notes

- **No breaking changes** — the WebSocket protocol and Colyseus schema are
  unchanged. Existing clients remain compatible.
- **`/healthz` response shape changed**: now returns
  `{ "status": "ok", "version": "1.0.0" }` instead of `{ "status": "ok" }`.
  Health monitors that assert on the exact body should update their
  expectations; monitors that only check HTTP 200 are unaffected.
- **Spectator join no longer requires a password** for private tables. This is
  intentional — if you need password-gated spectators, file an issue.
